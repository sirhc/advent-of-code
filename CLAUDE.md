# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Ground rule: no solutions unless asked

These puzzles are meant to be solved by the author alone. Do **not** write, sketch, or complete solution code, or reveal the answer, unless the user explicitly asks for it. Act as a brainstorming partner instead:

- Offer graduated hints, Zork-style: start vague (nudge toward what to look at), and get more specific only if the user asks for more.
- Naming or explaining a relevant algorithm or data structure (BFS, union-find, modular arithmetic, etc.) is fine, since the user may not know it. Don't write the puzzle-specific implementation.
- Clarifying the puzzle text, or pointing out a bug or flawed approach in code the user wrote, is fine. Point at where to look rather than handing over a fixed version.
- Editing non-solution files (README write-ups, Justfile, CLAUDE.md) is fine when asked.

## Layout

Personal [Advent of Code](https://adventofcode.com/) solutions, one directory per puzzle: `YYYY/DD/` (zero-padded day). There is no build system, no test suite, and no shared library code; every day is a self-contained script. Work started in 2024, so earlier years were committed retroactively (2018 is mostly missing).

Each day directory typically holds:
- `README.md`: the puzzle title, URL, and the author's write-up for Part One / Part Two (often with worked examples and reasoning). Generated by `just make-readme`, then filled in by hand.
- The solution script, with no fixed name (e.g. `hex.pl`, `antinode.pl`, `antinode2.pl`, `pass.zsh`). Part two is sometimes a second file (`foo2.pl`) and sometimes the same file edited.
- `input`: the puzzle input (gitignored along with `input*`, `example*`, `.env`, `.envrc`; don't expect it in a fresh checkout).
- Occasionally `test1`, `test2`, ... example inputs that *are* committed.

Early years (2015/2016) use extensionless `one`/`two` scripts. 2024+ uses `.pl` (Perl) mostly, with some `.zsh`/`awk` one-liner-style solutions.

## Running solutions

Scripts read the puzzle input from stdin or a file argument, so run them from inside the day directory:

```
cd 2024/08
perl antinode.pl input        # or: perl antinode.pl < input
perl antinode.pl test1        # against an example
```

Perl scripts use `#!/usr/bin/env perl` with `use v5.40;` (needs Perl 5.40+) and `<>` for input. Zsh scripts use `set -eu -o pipefail` and sometimes take the input file as `$1`. Some scripts call helpers in the same directory (e.g. `2025/04/remove.zsh` shells out to `printing-department.pl`).

## Justfile

The root `Justfile` is meant to be run **from within a day directory**: it derives the year and day from the current directory name (`invocation_directory`). It loads `.env` (needs `session=<adventofcode cookie>`) and requires `https` (HTTPie) and `htmlq`.

- `just get-input`: print the day's puzzle input (redirect to `input`)
- `just make-readme`: print a README skeleton (title scraped from the puzzle page) to stdout
- `just easter-egg`: show the hover-text easter eggs on the puzzle page
- `just store-session`: copy the `session` cookie from a Firefox profile (`$profile` pointing to the profile dir) into `.env`

## Conventions

- Match the surrounding style: 2-space indent, spaces inside parens/brackets in Perl (`my ( $a, $b ) = @_;`, `for my $y ( 0 .. $#$diagram )`).
- Solutions are puzzle-specific and often contain commented-out earlier attempts; leave those unless asked.
- Keep the README write-up for a day in sync when changing its solution approach.
